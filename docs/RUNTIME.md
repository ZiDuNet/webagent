# 运行配置说明

本文说明当前实现，而不是未来功能清单。配置入口是 **AI 配置 → 模型 / 助手 / 工具 / 运行设置**。React 聊天与 HTML 后台使用同一后端，主对话采用 OpenAI-compatible 协议，自研单 Agent loop。

[返回首页](../README.md) · [业务接入](INTEGRATION.md) · [架构设计](ARCHITECTURE.md) · [部署与备份](DEPLOYMENT.md)

## 1. 演示模式与真实模式

| 模式 | 执行方式 | 适用范围 |
| --- | --- | --- |
| 演示模式 | 本地确定性意图识别，调用真实业务工具；不调用 LLM | 首次运行、权限与审批演示、隔离回归 |
| 真实模式 | 请求配置的模型，由模型返回回答或工具调用 | 验证真实推理、工具选择、多模态与交互 |

新库默认 `demo_mode=1`，界面明确标识。真实模式缺少 Key、模型停用、协议错误时返回明确错误，不回退成假模型回答。演示意图只覆盖设备示例，不能代表接入任何业务后都有规则回复。

## 2. 模型与供应商

管理员在「AI 配置 → 模型」按**对话、语音、生图、决策**四类维护。页面参考 Octop 的模型池、供应商卡片与专用参数分区，使用同一 React / Ant Design 组件供后台与独立页面访问。供应商支持 12 个模板、自定义地址、同品牌多个连接，以及一个连接多个模型；Embedding / Rerank 在对话页折叠保留。完整说明见 [模型接入手册](MODELS.md)。

- **供应商**：OpenAI-compatible Base URL、API Key、额外 Header、超时、启停。
- **模型**：模型 ID、显示名、类型、上下文窗口、输出上限、文本/图片/工具/思考能力、推理等级、Temperature、Top P、价格、额外参数、默认值与启停。
- **发现与同步**：供应商 `/models` 用于模型列表；models.dev 和供应商元信息辅助预填参数，失败时可以手工输入与覆盖。
- **测试**：按分类实际请求供应商，不受业务演示模式影响；对话发送 Hi、STT 录音/上传、TTS 文本合成试听、生图返回预览、决策验证评分。实时语音不走文件测试，rerank 暂不支持自动测试。

类型字段包括 `chat`、`vision`、`asr`、`asr_realtime`、`tts`、`embedding`、`rerank`、`image_generation`、`decision`；只有 `chat/vision` 可作为默认对话模型。知识库索引、重排流程和生图业务工具仍需接入方开发。模型列表按需读取、12 秒超时并可取消；没有 `/models` 的供应商可直接填写 ID。同步保留专用类型及已保存协议。

API Key 使用 `WEBAGENT_SECRET_KEY` 派生的 Fernet 密钥加密落库，接口返回掩码。该根密钥必须稳定保留；丢失或直接换掉后，已有供应商与连接器密文不能正常解密。不要把凭据写进提示词、前端构建变量或工具参数。

### 辅助模型

| 用途 | 配置位置 | 留空行为 |
| --- | --- | --- |
| 主对话默认模型 | 模型页默认标记；助手可指定自己的默认模型 | 使用可用默认模型；没有可用项则报错 |
| 降级模型 | `fallback_model_id` | 不启用降级，不等于切回同一主模型 |
| 压缩摘要 | `compaction_model_id` | 跟随当前主模型；失败可回退本地摘要 |
| 会话标题 | `title_model_id` | 跟随当前主模型的标题生成逻辑 |
| 录音 ASR | `asr_model_id` | 禁用语音按钮 |
| 语音合成 TTS | `tts_model_id` | 关闭语音合成；不会回退到主模型 |
| 工具 / Skill 决策 | `decision_model_id` | 不允许开启决策筛选；运行中失效则保留已授权候选 |

同步的元数据是参考值，不是协议保证。特别是第三方网关的模型命名、推理参数和语音路由，必须按实际响应验收；价格字段用于估算费用，不替代供应商账单。

### 推理开关与强度

用户可选等级来自模型声明的 `reasoning_efforts`。前端不向所有模型强塞同一套“关闭/高低”参数：

| 模型协议 | 控制参数 |
| --- | --- |
| 标准兼容推理 | `reasoning_effort`；仅声明支持时映射 `off/none` |
| DeepSeek 混合推理 | `thinking: {"type": "enabled"}` 或 `disabled` |
| Qwen 混合推理 | `enable_thinking=true/false` |

`extra_params._reasoning.protocol` 可指定 `auto`、`effort`、`thinking`、`enable_thinking`；`can_disable=false` 可禁止关闭选项。显式关闭会覆盖额外参数中默认开启的值。固定推理模型不承诺可关闭，不支持的设置应报能力错误；`supports_reasoning=false` 时不发送推理控制参数。

上游只有返回思考字段时，页面才有思考内容。关闭深度推理可能减少等待，但不保证供应商首 token 延迟。

## 3. 助手、执行方式与运行上限

助手是配置模板，不是多个自治 Agent。普通 `agent` 助手在权限内多步推理；`report` 助手先执行预定义的只读采集，再让模型生成报告，不能把这类预采集解释为模型自主选工具。

执行方式是另一维度：

- **变更前确认**：写入和删除返回审批卡，批准后才执行。
- **完全访问**：管理员允许时跳过确认；不会扩大用户权限、助手白名单或工具范围。

审批持久化，同一审批原子抢占，批准时重新检查身份、会话、工具开关和权限。即使审批通过，业务 API 仍需验证对象归属与业务规则；工具接入方应为写操作提供幂等保障。

| 设置 | 新库默认值 | 含义 |
| --- | --- | --- |
| `max_iterations` | `6` | 一次运行的最大模型推理轮数；`0` 不限制次数，不再限定最多 12；助手字段为 `max_steps` |
| `max_tool_calls` | `12` | 一次运行最多工具调用数；`0` 不限制次数，不再限定最多 50 |
| `max_run_seconds` | `120` | 一次运行最长墙钟时间，范围 10–900 秒，次数不限时仍生效 |
| `user_daily_token_limit` | `0` | 每用户每日额度，`0` 不限制 |
| `default_approval_mode` | `confirm` | 默认先确认变更 |
| `allow_full_access` | `1` | 是否允许用户选择跳过确认 |

助手可覆盖步数、调用数、时长与上下文上限。助手中的 `max_steps=0` / `max_tool_calls=0` 保持“跟随全局”的含义；全局设为 `0` 后，未单独指定正数限制的助手也不限制次数。原有默认值不自动改变，管理员可分别关闭轮次或工具调用次数限制。取消次数限制不取消运行超时、业务权限、审批或并发控制。超过限制返回明确状态，不能把“达到最大步数”显示为操作成功。每日额度是轻量入口闸门，不是严格并发预扣费系统。

## 4. 工具范围与 Skill

候选工具按以下顺序计算：

```text
业务账号权限
  ∩ 助手工具白名单
  ∩ 管理员全局启停与四态配置
  ∩ 用户本轮选择
  → 可选 BM25 或决策模型筛选（不可同时开启，也允许全部关闭）
  → 固定启用工具补回 / 按需提供 Skill 加载工具
```

BM25 不是向量数据库，也不是权限机制。开启时通常对候选集召回 Top 16，固定工具与 Skill 工具可能使最终 Schema 数超过 16。两个开关都关闭时注入全部合规候选工具。发现管理页“已开启”但对话里没有某个工具，先检查账号权限、助手白名单、模型是否支持工具、四态与本轮选择，再查看检索记录。

### 决策模型

在「模型 → 决策模型」添加、测试并绑定评分模型，配置两个互斥开关、作用范围、阈值、触发数量与超时。打开任一开关会关闭另一个；可以都关闭。服务端用唯一 `tool_selection_mode=none|bm25|decision` 保证一致性，兼容 `bm25_enabled` / `decision_enabled` 两个布尔参数；请求同时开启两个会返回 422，不会部分保存。

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `decision_tools` / `decision_skills` | 都开启 | 决策筛选范围，至少选一项 |
| `decision_threshold` | `0.6` | 相关性分数达到阈值才保留 |
| `decision_min_count` | `8` | 范围内候选达到该数量才请求评分 |
| `decision_timeout_seconds` | `5` | 整个评分请求总时限，含重试，最大 30 秒 |

决策只接收已授权的工具名称/描述、助手允许的 Skill 名称/描述、最近最多 6 条对话（每条最多 1200 字）与当前请求；不附加业务 Token、工具结果原始记录、Skill 正文或长期记忆。对话正文可能含用户输入或先前回答中的业务数据。启用外部评分服务时，上述内容会发送给管理员配置的供应商。固定启用工具会补回；报告预采集与演示模式跳过决策。超过 200 个候选时保留全量并记录原因，不无声截断。

两种接入协议通过模型 `extra_params._decision` 配置：

- `chat_completions`：普通 OpenAI-compatible 模型输出 `{"scores":{"tool:name":0.8,"skill:1":0.4}}`，不会把评分 JSON 或评分器思考作为聊天正文输出。
- `decisions`：参考 Octop 的公开接口发送 `state + questions[id] = {type:"noul", instructions, criteria}`，从 `answers[id].noul` 等评分字段读取概率。预设 Jev / Microsoft 使用 OpenRouter 决策地址，Laya 使用已部署的本地评分服务；框架不会安装或启动 Laya。

专用协议的 `endpoint` 可用完整 URL 或同源绝对路径；留空使用供应商完整 Base URL。不同主机请另建连接；只有 loopback 地址允许不填 Key。对话评分使用 Base URL 下的 `/chat/completions`。模型同步保留手动决策类型和 `_decision` 协议配置。关闭开关时仍可编辑绑定、范围、阈值、数量门槛和超时，配置好后再启用。

超时、评分缺失、格式错误、模型停用均保留原始已授权候选，不调用 BM25。请求复用全局重试开关与退避参数，且受决策总时限约束；正常返回的低分/全零评分是有效结果，不等于服务失败。主模型仍负责具体工具调用与最终回答，业务权限和审批继续执行。

调用以 `purpose=decision` 记录，返回的 usage 合并到本轮与会话用量；供应商未返回 usage 时不伪造 token。会话详情展示筛选前后数量、模型、耗时、回退原因和候选分数；隐私开关关闭时隐藏筛选详情。React 和 HTML 聊天共用这条服务端流程。

管理员新增动态 HTTP 工具时，URL 主机必须固定；路径支持 `{device_id}` 这类 Schema 参数，其他参数按方法送入 query 或 JSON body。运行时注入当前用户 Bearer Token，定义不得覆盖 `Authorization`、`Host`、`Content-Length`。这不是开放给普通用户的任意 URL / 任意脚本执行入口。

Skill 加载是：名称与描述 → `load_skill(name)` 读取正文 → `read_skill_file(name, path)` 读取显式登记的参考文件。参数 `name` 使用技能 slug 或名称；不执行脚本，不遍历宿主文件，也不提升工具权限。详细接入见 [工具与 Skill 契约](INTEGRATION.md)。

## 5. 上下文预算与压缩

### 预算来源

近似计算如下，完整实现见 [`context.py`](../webagent/agent/context.py)：

```text
window = 模型 context_window，缺失时用全局上限，再回退 32768
max_context = max(2048, window 与正值全局上限的较小值)
reserved_output = min(模型 max_output_tokens, max_context / 2)
budget = max(1200, max_context - reserved_output - context_reserve_tokens)
```

全局 `context_max_tokens=0` 表示跟随模型，默认安全余量 `1600`。UI 切换模型时预算分母随当前模型重新计算，已有会话不会因此清空。显示的是本地估算的历史/摘要占用与预算，不是供应商精确 tokenizer 对完整 system、工具 Schema、图片等请求的计量；实际输入/输出以响应 usage 为准。

安全余量是从模型上下文窗口中额外扣除的输入缓冲，主要应对系统提示、工具定义等开销及 token 估算误差；输出上限已单独预留。它不是输出长度或推理次数限制，也不直接向供应商发送额外 token。填 `0` 确实关闭这份额外预留；工具较多、提示词较长时可适当提高。例如窗口 32768、输出预留 4096、安全余量 1600 时，历史与摘要预算为 27072。该值不能替代供应商对实际请求的窗口校验。

当前不提供“只携带最近 N 轮”的独立设置。轮数不能可靠代表长度，采用 token 预算、摘要与保留最近对话的方式管理。

### 三种触发

| 触发 | 条件 | 行为 |
| --- | --- | --- |
| 自动 | 历史与已有摘要估算超过预算，且自动压缩开启 | 摘要较早对话，保留最近部分 |
| 手动 | 调用压缩接口；完整 HTML 聊天页提供按钮 | 立即检查并执行，不够多时返回无需压缩 |
| 溢出兜底 | 上游返回上下文过长 | 本地按用户轮次边界应急裁剪后尝试恢复，不做无限重试 |

摘要按用户消息边界切分，默认 `compaction_keep_ratio=0.58`，可配 `0.2–0.9`。优先使用配置的摘要模型，留空用主模型；失败回退本地摘要并保留原因。摘要作为历史上下文而非新系统指令注入，不自动写入长期记忆。原会话记录仍供查看，不因压缩直接删除。

压缩记录包含触发方式、前后 token、摘要模型、耗时和错误。`run.phase` 只在真正开始压缩时提示，不在每次请求都显示“正在整理”。预算是估算值，单条巨大消息、工具结果和图片仍可能触发供应商限制。

## 6. 流式过程、断线与耗时定位

普通流式请求通过业务 BFF 的 `POST /api/agent/chat/stream`，主要事件有：

| 事件 | 页面含义 |
| --- | --- |
| `run.phase` | 身份确认、工具发现授权、上下文检查、实际压缩 |
| `step.started` | 等待首次模型响应或等待下一轮 |
| `thinking.delta` / `text.delta` | 真实思考 / 回答增量 |
| `tool.started` / `tool.finished` | 已脱敏参数、工具执行与结果 |
| `tool.approval_required` | 等待用户确认 |
| `retry` / `model.fallback` | 重试、降级 |
| `usage` / `run.completed` / `run.failed` | 本轮用量与最终状态 |

React 约 20fps 合批更新当前消息，心跳不触发正文重绘；Markdown 增量渲染，Mermaid 可解析时更新。尚未构成有效图语法的片段会等待更多内容，不宣称任何半段 Mermaid 都能正确显示。工具参数碎片不直接显示或保存，避免泄漏未脱敏内容。

过程默认一行，按事件发生顺序播放真实的准备动作、模型思考原文、已脱敏工具参数、工具结果以及回答增量（含 HTML 代码片段）。文本按标点或至多 36 个 Unicode 字符分段，在同一行覆盖显示；超过可用宽度时平移查看，避免只轮播“第几轮 / 已完成”等标签。播放积压时缩短停留时间；暂停、上一条、下一条、悬停和键盘焦点支持查看当前片段，手机端保留暂停按钮，完整内容可展开。系统设置减少动态效果时关闭自动切换和位移动画，直接跟随最新事件。

片段队列只在页面内存保留最近 300 段，不进入 localStorage 或独立落库；完整思考、工具结果和正文仍按原有数据策略管理。思考原文是否持久化继续由管理员 `store_reasoning` 决定。结束立即停止播放并自动收起，不为播放积压而延迟答案完成；重新打开历史会话也默认折叠。点击可查看对应轮次的完整思考、工具参数 / 结果和回答。计时与播放状态只更新过程组件，心跳不驱动正文重绘。没有收到模型输出时显示等待，不用定时器伪造工具动作；完成但没有真实工具记录时显示“未调用工具”。

React 对 HTML / HTM 围栏（含未闭合片段）和直接输出的 HTML 文档做增量提取；生成中不在正文铺开源码，过程行按顺序播放源码片段，展开可查看实际接收量，完整后显示紧凑产物卡片。普通 Markdown、Mermaid 和其他代码继续实时渲染。卡片默认仅标题、大小、「打开预览」「查看代码」；点击后才加载隔离预览或代码弹窗，保存图片、下载、发布与查看已发布记录都在弹窗中操作，不自动运行所有历史消息的 iframe。

**关闭页面不等于取消任务**：已启动任务继续在服务端执行；“停止接收”停止的是客户端接收。服务端提供运行 ID 与 `Last-Event-ID` 断线重放，接入方需保存游标并接回；不能把它等同于浏览器刷新后自动恢复所有 UI 状态。重放缓存与任务在内存，重启不恢复。

管理员在会话详情查看逐次 `llm_calls` 与工具记录：

1. 准备慢：检查身份接口、MCP 发现、网络与上下文压缩。
2. 模型慢：核对每次请求耗时、推理等级、模型、重试、工具 Schema 大小。
3. 工具慢：查看具体业务 API / 第三方调用耗时和错误。
4. 正文慢：区分上游输出速度与前端解析开销，不用伪造动画掩盖等待。

每轮 token、费用、耗时与会话累计可查询，费用按管理员配置单价估算；失败尝试也有调用记录，但供应商未返回 usage 的失败不能凭空算出真实账单。

## 7. LLM 重试与降级

SDK 自带重试关闭，由框架统一控制；**只重试模型请求，不自动重放业务写操作**。

| 设置 | 新库默认值 |
| --- | --- |
| `retry_enabled` | `1` |
| `retry_max_attempts` | `3`，包含首次尝试 |
| `retry_initial_backoff_ms` | `800` |
| `retry_max_backoff_ms` | `8000` |
| `retry_multiplier` | `2.0` |
| `retry_jitter` | `0.2` |
| `retry_honor_retry_after` | `1` |
| `retry_max_elapsed_seconds` | `60` |

可重试连接错误、超时、`408/409/425/429/500/502/503/504`；`401/403/404/422` 等明确客户端错误不做盲目退避。每次尝试记录用途、耗时、状态与错误；策略是全局配置，不按供应商再叠一层。

降级模型单独配置，未配置就不降级。启用也不表示所有错误都能被另一个模型修复；鉴权、权限和工具错误应按真实原因处理。

## 8. 图片与文件 ASR

图片走支持 `image` 能力模型的多模态消息；React 每条最多 4 张、每张不超过 3 MB、总计不超过 8 MB，支持 PNG/JPEG/WebP/GIF。能力元数据不替代供应商实际支持。

语音是“浏览器录音 → 后端转写 → 文本发送”。在模型语音页绑定可用 STT 后才启用按钮，浏览器录音需要麦克风权限与安全上下文（HTTPS 或受信任 localhost）。页面测试可上传或录制实际音频，不需要修改默认绑定。

| `extra_params._asr.protocol` | 路径/协议 | 用途 |
| --- | --- | --- |
| `auto` | 根据模型名和供应商地址判断 | 默认，仍需实际测试 |
| `transcriptions` | multipart `/audio/transcriptions` | Whisper / 文件转写兼容接口 |
| `chat_audio` | `/chat/completions` + `input_audio` | Qwen 文件 ASR 兼容模式 / Chat Audio |
| `dashscope` | `/api/v1/services/aigc/multimodal-generation/generation` | Qwen 原生语音接口 |

例如文件模型 `qwen3-asr-flash` 可配置：

```json
{"_asr": {"protocol": "chat_audio"}}
```

标准 Chat Audio 使用 Base64 与 `format`；Qwen 兼容路径默认使用音频 data URI。支持同源 `endpoint` 覆盖和 `data_format=base64|data_uri`，`_asr` 元数据不发给普通聊天请求。需要时通过系统 FFmpeg 把 WebM/MP4 转成单声道 16kHz WAV，缺少转换器会报错。

`*-realtime*` 通常是 WebSocket 模型，当前入口明确拒绝，不应把模型改名或强标为 `asr` 来绕过。已经能拉取到模型名、甚至类型自动识别正确，也不表示网关开放了对应转写路由。真实网关返回 404 / 路由不允许时，应核对供应商协议；隔离 Mock 回归通过不等于真实 ASR 已可用。

### TTS 语音合成

语音页独立维护 TTS 模型、协议、音色、格式和语速；清空默认 `tts_model_id` 并保存即关闭。OpenAI 使用 `/audio/speech`；DashScope 支持 Qwen3-TTS 与 Qwen-Audio3.x-TTS 两种已适配 HTTP schema。单次合成上限按协议为 600 或 4000 字，音频最多 10 MB，总时限不超过 90 秒，不自动重试收费请求。

`POST /api/agent/audio/speech` 返回二进制音频，响应为 `no-store`；普通用户只能用默认模型，管理员可指定 `model_row_id`。后台可试听和下载，PCM 提示需解码播放。当前聊天页未自动朗读每条回答，接入方可用 `SpeechClient` 或该 API 组合自己的播放控件。详细格式与示例见 [模型接入手册](MODELS.md#8-tts-协议)。

## 9. 记忆、隐私与数据保留

| 项目 | 当前行为 |
| --- | --- |
| 长期记忆 | 用户手动维护，相关启用记忆注入上下文，最多最近 20 条；不自动提取 |
| 思考原文 | `store_reasoning=0` 默认不写库，但本轮页面内存可展开；刷新后不恢复 |
| 管理员看正文 | `admin_session_content=1`；关闭后只返回元数据/统计，正文与工具内容隐藏 |
| 会话保留 | `session_retention_days=30`；Agent 启动时清理过期会话，`0` 关闭清理 |
| 发布内容 | 本地保存归属、URL、HTML 和版本，不随删除/清理会话删除 |
| 删除业务用户 | 删除业务账号，不自动删除 Agent 审计与会话；合规清理由接入方实现 |

会话、消息、用量、工具记录、审批保存在 Agent SQLite，不以浏览器或聊天文件代替授权存储。文件本身不会比数据库天然更小；真正影响容量的是正文、附件、工具结果、HTML 版本和保留政策。

当前会话清理是物理删除，不是长期归档调度；发布版本需单独制定容量与清理策略。备份时同时保留业务库、Agent 库和加密根密钥，不要只复制正在写入的 `.db` 而遗漏 WAL。生产部署、单 worker 限制与备份恢复见 [部署手册](DEPLOYMENT.md)。
