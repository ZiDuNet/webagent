# 会话与运行机制

## 1. 一次回答的真实流程

```text
接收业务 Token
  → 验证用户与助手
  → 计算可用模型、工具和 Skill
  → 可选决策评分，或启用 PI BM25 发现
  → 恢复 PI SessionManager
  → 官方 PI prompt / 工具循环 / 必要时压缩或重试
  → 文本、思考、工具结果与用量 SSE
  → 待审批或完成
  → 保存展示消息与 PI canonical entries 到会话 JSON，图片附件单独落盘
```

工具调用由主模型选择，不按关键词硬编码 CRUD。决策筛选是相关性预处理，不替主模型执行 Tool。没有真实模型配置不会产生「演示回复」。

## 2. 助手和模型

助手是一组角色说明、模型默认值、工具 / Skill 范围及预算，不是多 Agent 编排。新会话使用当前用户有权访问的默认助手，没有可用默认时按顺序回退。历史会话保留自身助手，不因管理员换默认而自动换人。

模型选择优先受锁定助手约束，其后为当前请求选择、助手默认、会话最近模型或全局默认。前端模型选择与后端执行同步；管理员可以禁止助手切换。

模型上下文取模型窗口与已设置助手 / 全局限制；输出长度、安全余量、压缩均受该窗口约束。配置的上下文上限不是模型容量自动扩容。

助手配置优先、全局运行设置兜底。助手字段为空（`null`）表示继承，而不是「关闭」；布尔字段的 `false` 是明确关闭，不会被全局 `true` 覆盖。当前可覆盖项包括：

| 类别 | 助手级字段 |
| --- | --- |
| 模型与上下文 | 默认对话模型、上下文上限、推理轮次 / 工具调用 / 运行秒数预算 |
| 语音 | 文件 STT、实时 STT、输入策略、识别后自动发送 |
| 朗读与通话 | 非实时 TTS、默认自动朗读、最长朗读字符、通话实时 STT / TTS |
| 对话体验 | 空态标题 / 说明 / 品牌徽标 / 快捷入口（每行 `标题\|描述`，最多 6 项，留空用内置示例）、默认推理强度、默认执行模式、是否允许完全访问 |
| 执行 | 长期记忆开关 |
| 范围 | 业务角色、工具白名单、Skill 范围、是否允许用户切换模型 |

品牌徽标由管理端上传后落在 `data/brand/<hash>.<ext>`，助手配置只保存 `brand/<hash>.<ext>` 相对路径；图片按原图比例自适应显示（桌面最大高度 132px、宽度 400px，移动端 92px / 260px），不裁剪、不强制拉成方块。换 Logo 或删除助手时会回收不再被任何助手 / 全局设置引用的文件；上传后未保存的孤立文件保留 24 小时后由清理器删除。读取地址是公开静态资源（`/api/agent/brand/<file>` 与 `/api/control/brand/<file>`，文件名带内容哈希），因此 Chat 在登录态确认前也能显示空态。

## 3. 真实过程 UI

- 过程区只保留一行「当前真实动作」，同一位置覆盖更新，不堆叠第一轮 / 第二轮标签，也不做固定间隔的假轮播。
- 文本、供应商返回的可见思考、工具参数摘要与结果、重试和压缩都会在上方这一行滚动呈现；旧内容不会被轮播重新播放。
- 不伪造思考；首 Token 未返回时保留真实等待和计时，可查看已完成的准备工作。
- 工具调用默认合并为一行，点击展开后查看参数与结果；不再按每次调用向下铺满消息区。
- 回答完成自动折叠过程，仍可手动展开；移除「简洁 / 标准 / 诊断」模式，展示策略不再由后端下发。
- 不单独显示「生成回答」阶段，因为正文区域本身已经开始流式渲染；也不显示内部「业务身份与权限已校验」步骤。
- Markdown 随累计文本更新；Mermaid 使用安全模式并对未完成语法防抖解析，不等整轮结束整理。
- HTML 流式输出期间在下方显示占位代码框并持续滚动，闭合后转为紧凑产物卡；不对半截 HTML 启动 iframe。
- React 更新节流约 50ms，过程内容和消息渲染保持稳定 key，避免每 Token 重建整个对话。

这里优化的是本地呈现和等待感，不能消除模型首 Token、上游排队、工具或决策本身的网络延迟。可在管理端查看用途耗时定位，而不是增加一个额外「整理回答」模型调用。

## 4. 会话持久化

聊天正文不写入 SQLite。每条会话对应一个 `data/sessions/<sessionId>.json`，保存：

- `messages`：前端展示消息、工具记录、附件相对路径、用量与可选思考。
- `pi_entries`：PI canonical session header 与 entries，用于恢复完整 PI 上下文；其中的图片也以相对路径保存，恢复时再读回 Base64。

图片附件保存在 `data/uploads/<sessionId>/`，展示消息和 PI canonical entries 都只记录 `path` / `mime_type` / `size`（PI entry 使用 `webagent_path`）；发给模型时才还原为 Base64。旧版内联 Base64 会在启动时一次性迁移为文件，失败则保留原数据并记录日志。PI 自带的图片缩放依赖 Photon WASM，当前版本在部分 Node/WASM 组合上会 panic 并把图片替换成文字提示，因此运行时关闭自动缩放，保留浏览器校验后的原图；超大图片应在前端限制或由供应商拒绝。

历史消息里的图片通过 `GET /api/agent/sessions/:id/attachments/:file` 回读：接口走同一套业务鉴权 / Token 鉴权，先校验会话归属再读取该会话自己的 `uploads` 目录，文件名只允许 `[A-Za-z0-9._-]` 且扩展名必须是受支持图片格式，因此无法跨会话或向上穿越目录。响应带 `Cache-Control: private, immutable`，浏览器可长期缓存；前端发送后立即清空输入框中的附件预览，图片跟着消息气泡展示，不再堆在输入栏。

SQLite 只保存会话归属、标题、增量统计、运行、审批、事件、记忆与发布元数据。旧版数据库中的 `messages` / `pi_state` 会在启动时迁移到文件，原始数据先备份为 `data/sessions/.legacy-conversations.json`，迁移成功后移除旧表。

启动时还会安全清理旧版 `pending_approvals` 表、`assistants` 的 `icon` / `greeting` / `mode` / `prefetch_tools`、`sessions` 的 `retry_count` / `error_count` 以及已废弃的旧 settings 键。清理前使用 `VACUUM INTO` 备份到 `data/runtime/backups/agent-pre-cleanup-<timestamp>.db`，成功后写入标记文件 `data/runtime/.legacy-schema-cleanup-v1`；不会删除会话 JSON 或仍需用于 Skill 迁移的 `skill_ids`。

编辑消息会删除后续消息、失效上下文和待审批记录；删除一条消息也删除其后续依赖消息。分叉复制选定范围内展示消息，清理审批，重新构建上下文，不执行历史工具。

默认会话保留 30 天，0 不自动清理。清理器每小时执行一次（启动时也执行），过期会话会同时删除会话 JSON、该会话工作目录、附件目录、`llm_calls` 与 `compaction_events`，并级联删除运行 / 事件 / 审批 / 问答；没有对应会话记录的孤儿工作目录与附件目录也会被回收。过期删除不会删除 PagePilot 发布档案。图片按会话落盘可避免会话 JSON 膨胀，但仍会占用磁盘；海量多模态历史宜接对象存储。

管理端「会话与诊断」支持服务端分页、搜索、查看和删除全部用户会话；清理前先预览截止时间和影响数量。删除会移除会话 JSON，并级联删除运行、审批与问答元数据；发布记录保留但解除 `session_id` 关联。`VACUUM` 只在没有运行任务时执行，用于回收 SQLite 已删除页；它不会压缩会话文件，也不是自动保留策略，更不能替代对整个 `data/` 的备份。

### 交互问答

`ask_user` 是框架内置的隐藏工具，不作为普通用户可选工具，但管理员可以全局停用。模型调用后：

1. 当前任务立即结束运行，状态为 `question_required`，不会继续猜测答案或执行后续工具。
2. 服务端保存加密问题、选项、单选 / 多选、自由文本和过期时间，并向 SSE 发送 `question.required`。
3. Chat / 业务前端渲染独立问答卡；刷新后可从消息 `metadata.question` 恢复 pending 状态。
4. 用户回答通过 `POST /api/agent/questions/:id/answer` 提交，服务端校验归属、选项、必填和过期状态，再把真实答案作为 continuation 继续原任务。
5. 用户取消、超时或发送新消息时，旧问题变为 `cancelled` / `expired`，不可重复回答。

新消息只会在模型、供应商、权限、消息内容和附件校验全部通过后取消旧问题；校验失败不会破坏仍可回答的问题。问答卡只用于补充信息，不能替代写入 / 删除操作的审批卡。

## 5. 后台任务与断线

每次 `run.started` 返回 run_id。SSE 连接和任务是分离的：

- 关闭 / 刷新 / 切换网页，只断开接收，任务继续。
- 刷新后通过会话 `active_run` 重新订阅，按 Last-Event-ID 回放。
- 停止按钮调用后端 cancel，传播 AbortSignal 给 PI 与连接器。
- cancel 不是数据库事务回滚，已经执行成功的业务写入不会自动撤销。
- 后端进程停止会中断任务，重启标记 interrupted；不持久化可跨进程恢复执行栈，不自动重放副作用。

持久化事件默认保留 1 天。未落库思考与决策诊断保留短期内存，完成约 1 小时后由清理器移除；进程重启即消失。慢客户端超过写缓冲限制会断开，前端可重连，避免反压无限占内存。

### 输入框语音识别

输入框左侧的语音按钮是普通输入辅助，不创建会话，也不直接触发模型：

- `file` 模式在停止录音后调用 `/api/agent/transcribe`，把识别文本一次回填到输入框。
- `realtime` 模式通过 `/api/agent/voice/dictate` WebSocket 在录音过程中持续回填 partial 文本，停止后提交 final。
- `auto` 模式优先使用实时槽位，未配置实时模型时回退文件槽位。
- 默认只回填输入框，用户可以修改后手动发送；`voice_auto_send=true` 时识别结果直接发送，不再回填输入框，实时听写的 partial 也会在发送时清空，避免同一句话显示两遍。
- 「识别中」只覆盖录音上传与转写本身；转写完成后按钮立即恢复，发送会话在后台继续，不会被整轮回答拖住。识别失败或连接意外断开也会清除该状态，可直接重试。
- 文件 STT、实时 STT、输入模式和自动发送策略都可在「运行设置 → 语音与朗读」配置；助手设置可逐项覆盖，留空继承全局。

### 实时语音通话

正式 Chat 右上角的「语音通话」不是另建一个会话：它严格绑定当前 `session_id`、助手、模型、工具选择与审批模式，关闭通话后文本历史仍在原会话继续。普通 TTS 朗读也在右上角，只读最终答案正文，自动过滤代码、HTML、Markdown、表格和链接；它不是实时通话。

- 需要管理员同时配置可用的实时 ASR 与 TTS；缺少任一项时按钮禁用，不做静默降级。
- 浏览器采集麦克风并下采样为 16 kHz 单声道 PCM，通过 `/api/agent/voice/stream` 的 WebSocket 发送；服务端适配供应商实时 ASR，不需要本地 ffmpeg。
- TTS 不等整轮回答结束：文本增量按句号、问号、分号切分；没有标点的长段落按约 120 字在逗号、顿号或空格处切块，实时 TTS 会提前预热连接。普通 TTS 音频按顺序播放，不重叠。
- 一轮正文结束后后台继续合成并发送剩余音频，不阻塞状态回到可交互；前端在最后一块音频播放完后提示可以继续说话，用户中途说话会停止播放并打断。
- 通话默认半双工：回答生成期间 TTS 播放不向 ASR 发送麦克风音频，从源头避免扬声器回声被识别成用户说话、形成自问自答循环。弹窗底部的「不打断 / 可打断」按浏览器记忆；开启打断后，需要约 250ms 持续人声才生效，并丢弃打断瞬间的扬声器尾音。
- 回答正文已经完成后，TTS 尾巴不再阻塞用户接话：检测到约 170ms 持续人声会先停止播放、丢弃一小段尾音，再开始录音，不需要等整段朗读播完。
- 前端 VAD 约 170ms 持续人声才开始录音、约 600ms 停顿才断句，短暂能量波动不会重置计数；播放结束后约 140ms 余音冷却。等待审批或补充信息时忽略麦克风。
- 实时 ASR 在通话开始和每轮识别完成后预连接，下一轮可直接送音频，减少 WebSocket 握手等待；预连接失败不影响后续按需重连。
- 服务端还有回声兜底：识别结果与本轮刚朗读的文本高度相似时按回声丢弃，不会创建新的运行。
- 语音回答仍走同一个 PI 运行与工具权限；遇到审批或 `ask_user` 时暂停，页面提示返回聊天处理，不能在通话弹窗里绕过审批。
- 关闭页面只会断开语音连接；后台文本任务是否继续仍由普通 run 生命周期决定。

## 6. 执行预算

| 配置 | 语义 |
| --- | --- |
| `max_iterations` | 单次回答 PI 模型轮次，0 不限 |
| `max_tool_calls` | 实际业务工具调用预算，0 不限；不含 PI tool_search / 知识 Skill 读取 |
| `max_run_seconds` | 全局运行限时，10–3600 秒，始终有效 |
| `user_daily_token_limit` | 每日模型 Token 限额，0 关闭 |
| `context_max_rounds` | 请求上下文最多保留多少用户轮次，0 不按轮次截取 |

助手预算 0 表示继承全局，非「该助手无限但全局有限」。PI 的 `finishTurn` 在达到预算或待确认后终止继续循环，不能靠在生命周期回调中返回不被核心识别的 continue 标记。

达到轮次或工具上限且尚需继续时返回 `status=limited`，页面显示「已达运行上限」和停止说明，不将空回答伪装为已完成。已执行工具不会回滚。

辅助摘要、标题与记忆调用独立记录用量，不计入主循环轮数。标题与自动记忆提取在后台执行，不延迟回答完成；进程关闭会取消这些辅助请求，不保证重启后续做。单次超长工具、没有响应取消信号的原生代码仍需业务开发者设置自己的网络超时。

## 7. 上下文压缩

自动压缩由 PI 主动执行，主要发生在两个路径：请求发送前估算上下文已接近模型窗口，或供应商明确返回上下文溢出错误。它不是等用户手动点按钮，也不是另起一个模型假装「整理回答」。安全余量在输出预算外预留提示词、工具和估算偏差空间，不是额外付费 Token。

框架用 `session_before_compact` 指定摘要模型与中文保留规则；没配摘要模型时使用当前主模型。PI 决定准备哪些历史和最近保留边界，框架不自己重写压缩循环。

- 摘要保留用户目标、事实、已执行操作、关键 ID、未解决事项和错误。
- 原消息不因压缩删除，只影响下次发送给模型的上下文。
- `compaction_keep_ratio` 决定最近内容保留比例；过小会丢失细节，默认 0.58。
- `context_max_rounds` 是额外的请求轮次裁剪，不是压缩阈值。裁剪保留 PI 压缩 / 分叉摘要与必要自定义上下文，不能把摘要一起丢掉。
- 压缩发生在下一次模型请求前，会延迟新回答的首 Token；但回答正文完成后会先发送 `answer.completed`，前端可以结束渲染、展示只读操作并开始 TTS，下一轮输入仍保持禁用，直到 `run.completed`。语音通话同样消费该事件，不等待压缩结束才结束朗读队列。
- 右上角压缩按钮执行手动压缩，不能在任务运行时与其竞争。手动压缩是幂等操作：会话内容太少或已经压缩过时返回 `{ ok: true, skipped: true, message }`，前端用轻提示告知而不是报错；真正失败（模型不可用、摘要请求失败）仍然返回错误。
- 压缩失败记录失败，不伪装成功。
- `compaction_events.after_tokens` 使用压缩后的实际上下文估算，不是摘要文本长度；管理端看到的是下一次请求的真实上下文规模。

## 8. 思考与隐私

`store_reasoning=false` 默认不持久化供应商 thinking blocks、消息 reasoning 或思考 SSE 原文。页面仍可实时展示与当前进程内短期回放，默认折叠，用户可展开。

开启保存后，后续思考可写入会话 JSON。关闭保存会清理已持久化思考；正在执行任务的最终落库也读取最新开关，避免又写回。此开关只控制供应商结构化思考字段，不自动识别用户正文或模型正文中的敏感信息。

框架不会生成、猜测或暴露供应商未返回的模型内部思维。`had_reasoning` 只表示收到过可见思考字段。

`admin_session_content` 关闭时，独立管理端不返回消息内容和原始决策 IO，但仍有 Token / 耗时等诊断元数据。关闭不等于数据从用户会话中删除。

## 9. 长期记忆

用户可查看、编辑、启用 / 停用、删除自己的记忆。每条记忆按稳定 `owner_key` 隔离，同一业务账号在 Web / 小程序等入口共用；默认助手可使用已确认记忆，助手可单独关闭。Chat 顶部「记忆」按钮显示已启用数量与待确认数量，待确认项可一次全部启用。

自动提取默认开启，提取结果默认 `enabled=false` 待用户确认，不立即影响其他会话。提取时向模型同时提供最近 12 条对话、本轮用户消息和已有记忆，要求去重 / 合并，单次最多写入 5 条；只处理用户明确表达的稳定事实 / 偏好，不从工具结果推断隐私，不提取密码密钥。管理员可关闭自动提取、设置提取模型（留空用摘要模型，再回退默认对话模型）并编辑规则。

助手「不认识」具体的人：它只认识业务接入层给出的稳定 `subject`。如果业务系统换账号、换浏览器导致 `subject` 变化，或使用匿名 Token 访客身份，记忆就不会跟随。跨端共享的前提是各端都向框架传入同一个业务主键。

规则是提示约束而非完善 DLP。对高隐私业务请关闭自动提取，或实现业务级审核与清理。当前不包含租户共享记忆库。

## 10. 重试与降级

主循环使用 PI 官方重试调度，后台配置是否启用、最多尝试次数、退避起点与上限，连接本身也有超时。辅助 completion 适配使用同一全局基线，记录 purpose / attempt / latency / error。

- 只重试模型请求，不重放写入工具或 PagePilot。
- 认证 / 参数类 4xx 不做普通辅助请求盲目重试；429 / 408 等可重试。
- 重试支持指数退避、倍率、抖动与 `Retry-After`，并受最大等待和总耗时约束；全局关闭后不再自动重试。
- 独立备用对话模型仅在主模型错误、尚无工具和正文输出时尝试。
- 决策失败保留原已授权候选，不切换为另一种筛选模式。
- 供应商自己的错误和速率限制可能改变延迟，应查看真实记录。

不是所有供应商都支持相同的 Retry-After、推理或音频参数；本版未把任意 provider 扩展参数当作统一标准保证。

## 11. 管理员定位慢请求

「会话与诊断」中的模型耗时区分 `decision`、`chat`、`compaction`、`title`、`memory` 等。执行诊断查看模型发送轮次和决策结果，原始决策输入输出短期保存。

按阶段判断：

1. 决策耗时：调高候选数阈值，或全部关闭 BM25 / 决策。
2. 模型耗时：关闭不必要的深度推理、选择合适模型、检查供应商排队。
3. 工具耗时：检查真实业务 API 或 MCP；不要让模型反复查询大结果。
4. 压缩耗时：使用合适摘要模型和窗口配置。
5. 页面延迟：检查反向代理 SSE 缓冲、主线程图表解析和图片大小。
